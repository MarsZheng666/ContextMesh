# 持续同步共享会话

[English](live-sync.md)

源设备只需首次**共享并同步**，每台接收设备只需首次**接收并跟随**。之后，新消息和已记录的工具执行会自动出现在**持续同步的会话**中。DSH 面板和 Codex 侧栏沿用各自现有的 ContextMesh 插件入口。

## 配置与使用

1. Server 和客户端使用兼容版本。Server 需要 schema **10** 和 `live-session-sync-v1` 能力；各设备使用同一 Server 命名空间的有效凭据，沿用已有访问边界。
2. DSH：在 ContextMesh 中找到会话，点击**共享并同步**。Codex：在发布页面选择已保存的会话和共享范围，再点击**共享并同步**。确认后，该范围也适用于后续记录。
3. Codex：在原生钩子设置中审阅并信任 ContextMesh 生命周期钩子；CLI 可使用 `/hooks`。钩子内容变化后需要重新审阅。它们协调新消息、工具开始/完成和轮次结束，共享接管期间需要保持启用。插件安装器提供钩子，不会关闭原生信任检查。
4. 在另一台设备打开**持续同步的会话**，选择会话，点击**接收并跟随**。保持 DSH 或 Codex 集成运行。关闭 Codex 面板不会停止后台同步；面板和会话启动钩子会在需要时重新启动同步进程。

跟随只展示共享记录，不调用模型或工具，也不会持续改写另一进程正在使用的 Codex 原生历史。需要在这台设备执行任务时，选择**在此继续**，选择本机目录并确认权限，沿用接收端自己的模型。

## 同步哪些内容

- 用户和助手的可见消息。共享视图不收集隐藏推理、模型重放状态、运行时策略提示和凭据文件。
- 完整共享时，包括工具开始、状态和已保存的结果；仅文本共享时不包含工具记录。工具参数和输出可能含项目敏感信息，首次确认也适用于后续记录。
- 工具完成后更新同一张记录卡片，不重复生成一张。预览不是完整归档，点击**查看记录**和**继续读取**可以分段查看正文。

DSH 原生事件已经持久化在远端 Server，共享视图直接引用这些记录。Codex 读取已保存的原生记录，并先把生命周期事件放入设备上的私有待发队列。较大的 Codex 记录使用经过校验的 512 KiB 数据块，保存到远端 PostgreSQL；不会用 1 MiB 限制整份会话。配置的存储容量配额仍然有效。

后台约每 750 毫秒检查一次，面板约每秒刷新一次；实际可见时间受原生保存时机和网络影响。这是记录级同步，不是逐 token 输出或远程终端直播。尚未保存结果的工具保持待完成状态。

## 断线与接管

接收端把每页记录及其读取位置一起保存。断线或进程重启后，只补齐缺失更新；上传请求即使丢失回执后重试，也不会重复生成记录。上传失败的 Codex 待发记录保留在本机，恢复连接后重试。升级时保留托管数据目录。

一个共享会话只有一个执行源。确认接管时，DSH/Codex 原生会话 ID 可以变化，但共享身份和已跟随设备保持不变。DSH → Codex 沿用接收端预检、停止源端及确认续跑流程。Codex → DSH 先检查接收端，等待当前 Codex 轮次及工具完成，再锁定预览的历史位置、准备 DSH，并在激活前切换写入归属；随后在 DSH 发送下一条指令。旧 Codex 会话的 ContextMesh 钩子会拒绝新的共享消息和工具启动。

若预览后源端又产生新记录，需要重新预览。已锁定的导入若失败或中断，应恢复原操作，而不是另建接管；未知源端状态不会被当成空闲。Server 不可达时，共享 Codex 源端的新消息和工具需要等待连接恢复，防止失联的旧设备在被接管后继续执行。已经产生的结果会保留在待发队列中。

工作区文件需单独同步，或使用现有的确认式文件传输。接收会话记录不会重放历史工具，也不会自动应用其文件改动。

## 升级

先执行 [schema 9 → 10 迁移](runtime.zh.md#从-schema-9-迁移到-10)，再更新各设备现有的单个插件，并审阅新增钩子。原有快照发布与导入仍然可用；不可变快照不会自动变成持续订阅。
