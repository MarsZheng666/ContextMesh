# 携带工作区文件继续会话

[English](files.md) · [跨机器交接](handoff.zh.md)

入口在现有插件的“远程会话 → 工作区文件与附件”。文件传输是需要确认的准备步骤，上传或应用文件本身不会转移会话写入权。

## 传输与接续

1. 两端配置同一个项目。Git 工作区映射到已有相同提交的仓库根目录；自行 clone 或 fetch，ContextMesh 不拉取远程仓库、不切换分支。
2. 在当前拥有会话的设备选择会话、目标，点击“检查待传文件”。检查新增、修改、删除路径以及附件清单。忽略文件不参与传输，预览 60 秒后过期。
3. 点击“上传这些文件”并确认，内容才会上传到你的 ContextMesh 服务，供选定目标使用。请检查是否包含私密资料，文件名检查无法识别所有秘密。
4. 在目标刷新“可用传输”，点击“在此设备预览”，检查显示的目录和文件清单。目标 Git 工作区必须干净、原始文件与基准一致，且没有正在使用该目录的 DSH 会话。先保留目标上的改动；不会自动合并或覆盖冲突。
5. 60 秒内点击“确认并在此应用”。映射或文件变化后需要重新预览。导入期间短暂拒绝创建新 DSH Agent；请停止可能写入这些文件的外部编辑器、构建任务和其他程序。
6. 显示“目标文件已就绪”后，从来源正常交接。两端再次核对已确认的内容和附件引用，再转移写入权。之后发生修改需重新传输；预检失败时来源仍可继续。

迁移工作树的最终内容，不迁移 Git 暂存区、分支或提交。来源已暂存的修改在目标表现为未暂存修改；重命名可能显示为删除加新增。二进制内容和普通文件的可执行标志保留。普通非 Git 会话仍不复制目录内容，其支持的文件附件可以通过此流程传输。

## 附件与限制

支持 DSH 原生**文件**附件：通过公开附件接口读取，校验 SHA-256，再通过目标附件接口保存。原始附件 ID、名称、字节和 Session 事件保持一致。跨模型接力仍仅支持文本和已完成工具；传输了附件不代表其他模型可以使用它。

单次上限：**64 个工作区文件、32 个文件附件、单个 1 MiB、合计 4 MiB**。两端更新同一个插件，服务端需声明 `workspace-transfer-v1`。

暂不支持图片、spill、submodule、符号链接、硬链接、非常规文件、Git assume-unchanged/skip-worktree 条目、ignored 文件和运行中的进程。拒绝 `.git`、`.env`、`.ssh`、`.aws`、私钥和常见凭证文件名。出现禁止路径时阻止整个包，不会悄悄略过后把不一致的工作区视为可接续。确认前检查完整清单。

## 中断与回滚

修改文件前，目标会在 ContextMesh 状态目录保存私有、持久化的恢复日志和原始字节。中断后阻止自动重试，可选择“回滚导入的文件”或通过传输 ID 调用 CLI。回滚先检查全部受影响文件的哈希和模式；任一文件存在后续编辑就停止。先单独保留这些编辑，再将文件核对至记录中的导入版本或原始版本后重试，没有强制覆盖选项。

回滚成功会恢复原始工作区文件，并撤销目标就绪状态。不可变附件缓存保留，不重写会话历史。应用成功但响应丢失时，预览仍有效可重试；重启后重新预览。来源上传在预览有效期间复用同一个计划 ID；来源重启后重新检查生成计划，不能用旧确认处理变化后的内容。

服务端传输包 **24 小时**后过期，新上传时清理过期内容，但仍被活动或待恢复交接引用的内容保留。每个 namespace 最多保留 **32 个包**。本地恢复日志和备份保留，未处理完导入前请保存传输 ID，不要删除状态目录。服务端过期后，CLI 回滚仍可读取本地日志，但需要服务可连接并确认没有活动交接。不能通过删除日志来代替处理部分应用的文件。

继续使用已有 HTTPS/SSH 传输及 namespace 信任规则。服务端是普通 PostgreSQL 存储，不是端到端加密或项目级分享系统。配对设备属于同一所有者信任域，目标设备选择负责路由，不隔离所有者或服务端管理员。

## CLI

通过运行中的 DSH 私有控制 socket 操作，按需增加 `--state-dir PATH`；每次确认修改前先检查返回的文件清单。

```sh
# 来源
pnpm cli workspace-plan SESSION_ID TARGET_NODE_ID
pnpm cli workspace-export PLAN_ID --confirm

# 目标
pnpm cli workspace-list
pnpm cli workspace-preview TRANSFER_ID
pnpm cli workspace-apply TRANSFER_ID --preview-id PREVIEW_ID --confirm

# 目标就绪后，来源交接
pnpm cli handoff SESSION_ID TARGET_NODE_ID

# 目标回滚；交接前操作，或先确认没有活动交接
pnpm cli workspace-rollback TRANSFER_ID --confirm
```

## 升级

服务端使用 schema **6**。升级前备份 PostgreSQL 并停止旧写者，同时更新服务端和参与设备。schema 1–5 的迁移保留 Session header 和事件，增加带有效期的文件传输记录。旧服务端拒绝 schema 6，回退需要恢复备份，DSH 原生 Session 格式不变。
