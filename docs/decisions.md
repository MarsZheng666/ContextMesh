# ContextMesh 方向与决策记录

日期：2026-10-26。

## M0 实施更新

用户已要求开始 M0。实现采用 TypeScript ESM、Node 24、Fastify、Zod/JSON Schema、pg 与 PostgreSQL；插件兼容性固定到官方 npm 包 0.2.1-rc.3、Cordis 4.0.5。具体依赖由 pnpm-lock.yaml 固定。先前“建议”表保留为预研时的历史记录；当前实现与限制见 [M0 说明](m0.md)。

为完整保留合法 JSON 中的 NUL 与未配对 Unicode，header、事件和幂等结果使用 JSON 文本存入 TEXT，序号和写权采用独立列；HTTP 校验禁止自动类型转换。额外 incarnation 区分同一 ID 在空 Session 删除后的重用。异常写权不自动接管，只有确认旧执行者已停止且旧租约到期后才能显式恢复。

## 本轮设计建议，尚非用户既定决策

| 项目 | 建议 | 原因 |
| --- | --- | --- |
| 接入点 | 提供 `ctx.sessionPersistence` 的远程后端，保留上游 agent-loop | 官方已经提供存储服务接口和恢复生命周期 |
| 服务端 | TypeScript / Node.js，单个服务实例 + PostgreSQL | 与首个插件共享语言；事务支持连续日志、写权和幂等请求 |
| 存储分层 | 保留原生日志；另设可移植任务上下文 | 原生事件不能无损等同于任意 Agent 的历史格式 |
| 第一个可验收范围 | 文本、单用户、可协作停止的同 Harness 双机器接续 | 先验证数据持久性和生命周期，再加入附件与更多运行时 |
| 模型接力 | 同 Harness 显式切换 provider/model，并校验能力 | 已存在模型选择事件；仍须验证目标模型适配器 |
| 异构 Agent | 以独立 TaskContext 导出/导入开启新 Session | 避免宣称跨运行时直接重放原生日志 |

这里的“分布式”首先指多个客户端通过远程服务共享持久上下文。MVP 不提供多区域、多主写入或分布式数据库。
