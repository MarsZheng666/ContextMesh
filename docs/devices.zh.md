# 接入另一台设备

[English](devices.md) · [部署说明](deployment.md)

每台设备继续安装唯一的 `dsh-contextmesh-handoff` 插件及本仓库锁定的运行时。先启动或升级 ContextMesh 服务端。服务端使用 schema **5**，迁移前备份 PostgreSQL 并停止旧写者，保留原有 Session header 和事件日志。

## 配对新设备

在已有的管理设备中打开“远程会话 → 服务连接 → 添加或撤销设备”，输入新设备名称，生成配对码。邀请只能兑换一次，最长十分钟失效，只分享给你信任的自有设备。

在新设备的仓库目录运行：

```sh
pnpm cli setup
```

向导询问可访问的服务地址和配对码，自动保存私有配置。远程地址使用 HTTPS。回环地址表示新设备自己；使用 SSH 时，先建立新设备自己的通道并保持运行。配对不会安装 SSH 密钥，也不管理 SSH 登录。

配置后重启 DSH。默认读取 `$DSH_HOME/contextmesh/connection.json`；未设置 `DSH_HOME` 时读取 `$HOME/.dsh/contextmesh/connection.json`，也可通过 `CONTEXTMESH_CONFIG` 指定路径。文件权限为 600，所在目录必须为 700，不会隐式覆盖已有配置。每台设备使用独立 DSH home，配对提供稳定的设备身份。

响应丢失时，在邀请过期前使用完全相同的服务地址和配对码重新运行设置。私有重试文件保留 claim 身份，服务端返回同一凭证，不重复发证。需要放弃中断操作时，明确移除配置目录中的 `.pairing-attempt.json`，然后申请新邀请。不要把私有配置或重试文件提交到 Git 或复制给其他设备。

## 管理凭证与设备凭证

原有 `CONTEXTMESH_TOKEN` 和显式插件配置继续有效，优先于连接文件。原始服务令牌是管理凭证，应妥善保管。管理设备可在同一面板中创建邀请、查看设备和撤销凭证；已配对设备不能操作这些管理接口。设备丢失时撤销它，再为替代设备生成新邀请。

服务端只保存设备令牌和配对码的哈希。撤销后的新请求会被拒绝，已经接收的工作可能仍需完成或停止；撤销不会撤销外部工具副作用。已使用的邀请不能重新激活已撤销凭证。

当前仍是单用户服务：所有配对设备共享服务端配置的 namespace 及其会话。设备凭证约束设备注册和按设备划分的控制请求，不等于项目级权限或独立用户账号；这些需要后续权限层。DSH 浏览器登录与 ContextMesh 配对仍然独立。

## 连接中断

面板保留最后一次已知列表，显示连接错误，并按有上限的退避间隔重试读取。客户端保留草稿，发送前重新检查服务和写入权，不排队离线写入，也不自动接管失效写者。传输层对结果不确定的变更使用原请求身份重试。

启动 DSH 时保持服务和必要通道可访问。失败后先恢复连接再重试发送。写入租约失效时，仍需在确认旧进程及工具停止后执行[显式恢复](handoff.zh.md#中断与恢复)；重新连接不代表允许自动恢复或工具重放。
